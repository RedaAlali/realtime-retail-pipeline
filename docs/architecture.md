# System Architecture

This document provides a detailed overview of the end-to-end architecture of the **Real-time Retail Analytics Pipeline**.

## Architecture Diagram

```
┌─────────────────────────────────────────────────────────────┐
│  Batch: product_catalog.csv, store_locations.csv → PostgreSQL
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│  Producer → Kafka (transactions, refunds) → Spark Streaming │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│  PostgreSQL ← ML Service (RFM, K-Means, Apriori)            │
│       ↓                                                      │
│  Streamlit Dashboard (KPIs, Charts, ML Insights)            │
└─────────────────────────────────────────────────────────────┘
```

## Component Details

### 1. Database Layer (`db/` and `postgres`)
* **Technology**: PostgreSQL 15
* **Role**: Star schema storage.
* **Initialization**: The DB is seeded automatically during first run with SQL scripts located in `db/init/`. The source datasets are under `db/data/`.
* **Primary Tables**:
  - `dim_products`: Dimensional product catalog (Product ID, Name, Category, Price).
  - `dim_stores`: Dimensional store locations (Store ID, Store Name, Region).
  - `transactions`: Real-time transaction facts (Transaction ID, Timestamp, Customer ID, Product ID, Store ID, Quantity, Price, Total Amount).
  - `refunds`: Refund facts (Refund ID, Timestamp, Transaction ID, Refund Reason, Refund Amount).
  - `product_metrics_minute`: 1-minute tumbling window metrics generated by Spark.
  - `customer_segments`: ML-calculated RFM clustering results.
  - `product_associations`: ML-calculated market basket association rules.

### 2. Transaction Producer (`services/producer/`)
* **Technology**: Python + `kafka-python`
* **Role**: Generates randomized mock retail transactions and refunds.
* **Event Frequency**: Regulated by the `PRODUCER_SLEEP_SECONDS` setting. Emits transactions to the `transactions` Kafka topic and simulates refund events (approximately 10% rate) to the same topic.

### 3. Spark Structured Streaming (`services/spark/`)
* **Technology**: Apache Spark 3.5.1 + Python (PySpark Structured Streaming)
* **Role**: Consumes real-time streaming events from Kafka, performs validation/parsing, compiles running aggregations, and writes transaction facts, refund facts, and aggregated window metrics back to PostgreSQL.
* **Key Mechanisms**:
  - Exactly-once processing facilitated by Spark checkpointing.
  - 1-minute tumbling windows on transaction timestamps, using a 5-minute watermark to handle late arriving data.

### 4. Machine Learning Daemon (`services/ml_service/`)
* **Technology**: Python + `scikit-learn` + `mlxtend` + `psycopg2`
* **Role**: Runs background analysis on Postgres datasets on a regular poll interval:
  - **RFM Customer Segmentation**: Calculates Recency, Frequency, and Monetary scores per customer, applying a `K-Means` clustering model to label customer segments.
  - **Product Recommendations (Apriori)**: Conducts Market Basket Analysis to extract confidence, support, and lift values for product pairings, facilitating recommendation algorithms.

### 5. Analytics Dashboard (`services/dashboard/`)
* **Technology**: Streamlit + Altair
* **Role**: Frontend reporting interface.
* **Views**:
  - Live revenue, transactional, and refund KPIs.
  - Interactive charts illustrating revenue splits by product category, top products, and hourly/minute trends.
  - Regional store efficiency charts.
  - Visual distribution of customer segments.
  - Tabular list of product recommendation rules.
